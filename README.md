# Ark Coding Plan Usage（SwiftBar 插件）

[English](README.en.md) | 简体中文

在 macOS 菜单栏实时查看**火山方舟（Volcengine Ark）Coding Plan** 的小时 / 周 / 月度用量。

菜单栏一行，每 4 秒在三档用量之间轮换；下拉菜单里有进度条、刷新倒计时和快捷操作。

- 本仓库（fork）：<https://github.com/zhangjizhong-86/ArkCodingPlanUsage>
- 上游原作者：<https://github.com/xiaokaiyyy/ArkCodingPlanUsage>

> 本 fork 相对上游做了两处核心改动：**菜单栏由「只显示最高一档」改为「三档轮换」**，以及**增加本地缓存与热/冷双路径，避免每次刷新都请求接口**。详见[与上游的差异](#与上游的差异)。

## 界面效果

菜单栏标题单行，在三档之间轮换（每档停 4 秒）：

```

```

下拉菜单：

```

────────────────────────────────
小时用量距刷新还剩 3小时12分钟
周用量距刷新还剩 5天4小时
```

## 依赖与安装

**环境要求**

- macOS
- [SwiftBar](https://github.com/swiftbar/SwiftBar)（推荐，`brew install --cask swiftbar`）或 BitBar
- Python 3（脚本仅使用标准库，无第三方依赖）

**安装步骤**

1. 安装并启动 SwiftBar，设置一个插件目录（例如 `~/Library/Application Support/SwiftBar/Plugins`）。
2. 把 `ark_usage.4s.py` 放进该插件目录，并赋予可执行权限：

   ```bash
   chmod +x ark_usage.4s.py
   ```

3. 修改脚本首行的 shebang，指向你自己的 Python 解释器：

   ```python
   #!/usr/bin/env python3
   # 或写成绝对路径，例如：
   #!/opt/homebrew/bin/python3
   ```

4. SwiftBar 会自动识别文件名里的刷新周期（`.4s.` = 每 4 秒），并立即执行一次。

> 刷新周期完全由**文件名**决定：`ark_usage.4s.py` → 4 秒。若想降低资源占用，把文件重命名为 `ark_usage.10s.py` 或 `ark_usage.1m.py` 即可（同时把脚本里的 `ROTATE_SECONDS` 改成相同的秒数，见[菜单栏轮换策略](#菜单栏轮换策略)）。

## 配置 Cookie

插件通过火山控制台的内部接口拉取用量，需要你**已登录控制台**的 Cookie。整个配置只需要做一次，之后 Cookie 过期时再更新即可。

1. 浏览器登录 [火山方舟控制台](https://console.volcengine.com/ark) 的「开通管理 / 套餐订阅」页面。
2. 打开开发者工具 `F12` → `Network`，刷新页面，找到 `GetCodingPlanUsage` 请求。
3. 右键该请求 → **Copy → Copy as cURL**（或 "复制为 cURL"）。
4. 点击菜单栏图标 → **「从剪贴板更新 Cookie」**。

脚本会从剪贴板里解析出 `Cookie` 与 `x-web-id` 并写入 `~/.config/ark_config.json`，无需手动编辑。

> 也可以用「Copy as cURL (bash)」以外的格式，脚本兼容 `-b '...'` / `--cookie '...'` / `Cookie: ...` 几种写法。

**Cookie 有效期提示**

- 距上次更新 **≥ 7 天**：菜单栏出现 `⚠️`
- 距上次更新 **≥ 14 天**：菜单栏出现 `🔴`
- 接口返回 401/403：菜单栏显示「Cookie 过期」

## 菜单栏轮换策略

这是本 fork 的核心行为，值得单独说明。

**1. 触发频率 = 文件名里的周期**

SwiftBar 依据文件名 `ark_usage.4s.py` 每 **4 秒**执行一次脚本。

**2. 轮换周期与刷新周期刻意保持一致**

脚本内 `ROTATE_SECONDS = 4`，与刷新周期相等。这样**每次刷新都恰好切到下一档**，既不会有"刷新了但界面没变"的空转，也不会跳过某一档。

**3. 无状态的时间轮换**

当前显示哪一档，完全由**系统时钟**决定，不依赖任何本地状态文件：

```python
idx = int(time.time() // ROTATE_SECONDS) % len(records)
```

这意味着：

- 脚本被反复执行也不会累积状态，重启电脑 / 重启 SwiftBar 都能立刻接上正确的档位；
- 多个实例（或手动执行）得到的档位始终一致；
- 一轮 = 3 档 × 4 秒 = **12 秒**，循环顺序为 **小时 → 周 → 月**。

**4. 标题宽度恒定**

标题格式为 `档位简称 + 空格 + 百分比 + 可选标记`，例如 `时 23%`、`月 26%`。

为了让菜单栏图标**不随数值抖动**（避免菜单栏其它图标左右乱移），做了两件事：

- 使用**等宽字体** `Menlo`（`font=Menlo`）。macOS 默认字体 SF Pro 的数字是比例宽度——`1` 比 `0` 窄，靠补空格对齐无效，实测同一标题在不同数值间宽度会差约 8pt；
- 百分比**右对齐到固定 2 位**并**封顶显示 99**（`PCT_DIGITS = 2`、`PCT_MAX = 99`）。这样标题恒为 5 个字符，宽度完全一致（实测 @ Menlo 12 恒为 44.3pt）。到 100% 时会多占一位，所以菜单栏封顶显示 `99%`，**下拉菜单里仍然是真实值**（如 `100.0%`）。

## 性能影响

轮换越"跟手"，脚本被执行的次数就越多。这部分是本 fork 引入缓存的主要原因。

**热 / 冷双路径**

| 路径 | 触发条件 | 行为 |
| --- | --- | --- |
| 热路径 | 缓存仍在有效期内 | 只读纯文本缓存并打印，**不导入 `json` / `pathlib`**，不发网络请求 |
| 冷路径 | 缓存过期 / 上次失败退避结束 / 配置文件被改动 | 导入 `json`、`urllib`，请求接口并写回缓存 |

相关参数：

- `API_CACHE_TTL = 60`：接口结果缓存 60 秒，即**最多每 60 秒才真正请求一次接口**（60 秒内会刷新 15 次，只有 1 次打接口）。
- `API_RETRY_COOLDOWN = 30`：请求失败后 30 秒内不重试，避免网络异常时反复打接口。

**实测数据**

测量方式：`resource.getrusage(RUSAGE_CHILDREN)`，环境为 Python 3.13.13（miniforge）、Apple Silicon macOS。

| 场景 | 单次 CPU | 单次墙钟 |
| --- | --- | --- |
| 热路径（读缓存，20 次均值） | **≈ 18 ms** | ≈ 20 ms |
| 冷路径（含 HTTP 请求） | **≈ 409 ms** | ≈ 631 ms |

**按 4 秒刷新推算的每日开销**

- 每日执行次数：`86400 / 4 = 21,600` 次
- 其中冷路径：`86400 / 60 = 1,440` 次；热路径：`20,160` 次
- 每日 CPU ≈ `1,440 × 409ms + 20,160 × 18ms ≈ 588 + 365 ≈ 952 CPU·秒/天`
- 折算下来约为**单核的 1.1%**（持续占用，但在多核机器上几乎无感）
- 每日接口请求：**最多 1,440 次**

**与不轮换的原版（5 分钟刷新）对比**

| | 本 fork（4s 轮换 + 缓存） | 原版（5m，无缓存） |
| --- | --- | --- |
| 每日执行次数 | 21,600 | 288 |
| 每日接口请求 | ≤ 1,440 | 288（每次都请求） |
| 每日 CPU | ≈ 952 CPU·秒（单核 ~1.1%） | ≈ 118 CPU·秒（单核 ~0.14%） |

可以看到：执行次数涨了 75 倍，但**接口请求只涨了 5 倍**——这正是 60 秒缓存的收益。

**如何降低开销**

1. 把文件名改成更长的周期（如 `ark_usage.10s.py`），同时把 `ROTATE_SECONDS` 改为相同值；
2. 调大 `API_CACHE_TTL`（如 300 秒），接口请求量按比例下降；
3. 完全不轮换，回到单档显示（把 `LEVEL_ORDER` 之外的处理简化或在菜单栏固定显示一档）。

> 说明：冷路径数值取自同一份请求逻辑（`fetch_quota`）的实测，两者的接口调用完全一致。

## 下拉菜单

- 三档用量进度条，当前菜单栏正在显示的那一档前面带 `▶` 标记；
- 三档的**刷新倒计时全部展示**，不随菜单栏轮换变化；
- 「切换为圆点/方块进度条」——切换进度条样式，写入配置文件后立即生效；
- 「从剪贴板更新 Cookie」——见[配置 Cookie](#配置-cookie)；
- 「打开火山控制台」——跳转到火山方舟控制台。

## 自定义配置

脚本顶部的常量可直接修改：

| 常量 | 默认值 | 说明 |
| --- | --- | --- |
| `ROTATE_SECONDS` | `4` | 菜单栏轮换周期（秒），需与文件名里的刷新周期一致 |
| `TITLE_FONT` | `Menlo` | 菜单栏字体，等宽字体才能保证标题宽度恒定 |
| `TITLE_SIZE` | `12` | 菜单栏字号 |
| `PCT_DIGITS` | `2` | 百分比占位数（右对齐） |
| `PCT_MAX` | `99` | 菜单栏显示上限，避免出现 3 位数字导致变宽 |
| `API_CACHE_TTL` | `60` | 接口结果缓存有效期（秒） |
| `API_RETRY_COOLDOWN` | `30` | 请求失败后的重试冷却（秒） |

**文件位置**

| 文件 | 路径 | 用途 |
| --- | --- | --- |
| 配置 | `~/.config/ark_config.json` | Cookie、`x-web-id`、进度条样式 |
| 缓存 | `~/.config/ark_usage_cache.txt` | 纯文本用量缓存与时间戳 |

缓存是 `key=value` 的纯文本格式，便于热路径在不导入 `json` 的情况下解析：

```
written_at=1755000000.000
config_mtime=1754000000.000
bar_style=dots
error=
session=38.5000|1755003600
```

## 与上游的差异

本 fork 保留上游全部功能，主要差异：

| 维度 | 上游 `ark_usage.5m.py` | 本 fork `ark_usage.4s.py` |
| --- | --- | --- |
| 菜单栏内容 | 只显示**三档中用量最高**的一档百分比 | **三档轮换**（时 → 周 → 月） |
| 数据获取 | 每次刷新都请求接口 | 热/冷双路径 + 60 秒缓存 |
| 菜单栏字体 | 系统默认（宽度随数值变化） | 等宽 `Menlo` + 固定 2 位，宽度恒定 |
| 进度条样式 | 固定一种 | 圆点 / 方块可切换（写入配置） |
| Cookie 更新 | — | 一键从剪贴板解析更新 |
| 刷新周期 | 5 分钟 | 4 秒 |

## 常见问题

| 问题 | 处理 |
| --- | --- |
| 菜单栏显示「未配置 Cookie」 | 先完成[配置 Cookie](#配置-cookie) |
| 菜单栏显示「Cookie 过期」 | Cookie 失效（接口返回 401/403），重新复制 cURL 更新 |
| 菜单栏出现 `⚠️` / `🔴` | Cookie 已 7 / 14 天未更新，建议尽快更新 |
| 菜单栏出现 `⚠️`（数值后） | 本次请求失败，正在展示上一次的缓存数据 |
| 图标宽度还是会动 | 确认 `TITLE_FONT = "Menlo"` 未被改动；若换成非等宽字体会重新出现抖动 |
| 想降低 CPU 占用 | 见[如何降低开销](#性能影响) |
| 插件不刷新 | 确认文件有可执行权限、shebang 指向有效的 Python、文件名含周期（如 `.4s.`） |
